## 전체 구조 개요

```
[사용자]
    ↕ 앱 API
[내부망 — 교보 직접 운영]
    ↕ 트랜잭션 요청 / 이벤트
[내부망 Node.js 서비스 — 교보 운영]
    ↕ 서명 요청          ↕ 이벤트 수신
[VASP — 위탁]      [EVM 블록체인]
    ↕ TX 브로드캐스트
[EVM 블록체인]
```

### 2. 내부망 — 교보 직접 운영

**교보가 직접 구축·운영하는 영역. 커스터디 없이도 여기가 핵심.**

#### 비즈니스 로직
| 컴포넌트 | 설명 |
|---|---|
| 이벤트 조건 판단 | 걷기 n보 달성 여부, 쿠폰 발행 조건 처리 |
| NFT 요청 생성 | 발행·소각·전송 요청을 VASP API로 전달 |
| 벌크 발행 관리 | 수만 명 동시 배포, 배치 처리 + 재시도 로직 |
| 승인 워크플로우 | 대형 트랜잭션 내부 승인 프로세스 |

#### 데이터 관리
| 컴포넌트 | 설명 |
|---|---|
| 내부 원장 | 사용자별 NFT 보유 현황, 온체인 상태와 동기화 |
| 사용자 서비스 | 사용자 인증, 지갑 주소 매핑, KYC 연동 |
| 감사 로그 | 모든 발행·소각·전송 이력 |

#### 거버넌스
| 컴포넌트 | 설명 |
|---|---|
| 멀티시그 보조키 | 교보 보유 서명키. 대형 TX는 교보 승인 없이 불가 |
| Admin 대시보드 | 컨트랙트 Pause·정책 변경·발행 현황 모니터링 |

### 3. 내부망 Node.js 서비스 — 교보 운영

| 컴포넌트 | 역할 |
|---|---|
| Webhook Receiver | 온체인 이벤트 수신. 즉시 큐 적재, 직접 처리 금지 |
| Redis Streams | 수신·처리 분리. 멱등성 보장. Dead Letter Queue |
| Relayer Service | 내부 → VASP API 요청. TX 상태 추적 |
| VASP API Gateway | VASP 연동 단일 채널. 인증·Rate Limit·로깅 |
| Private RPC Node | 전용 EVM 노드. Infura 등 외부 의존 제거 |

### 3.5 멀티체인 추상화 레이어 (IBlockchainAdapter)

> 내부망 코드에서 블록체인 체인 구현을 분리하는 Strategy Pattern 레이어. 당사 직접 구축.

| 컴포넌트 | 설명 |
|---|---|
| IBlockchainAdapter | 발행·소각·잔액 조회·TX 검증·이벤트 구독을 체인 무관하게 추상화 |
| EVM 어댑터 | Phase 1 현재 구현체 — ethers.js 기반 Ethereum/Arc 연동 |
| XRPL 어댑터 | Phase 2 추가 예정 — XLS-20 NFT, TrustSet, reserve·fee 체계 |
| Circle ARC 어댑터 | Phase 2·3 추가 예정 — 프로그래머블 월렛, Account Abstraction |

**핵심 원칙:** VASP가 체인 구현체 선택·어댑터 주입. **비즈니스 로직·원장·감사 로그는 체인 교체에 무관하게 유지.**

### 4. VASP — 외부 위탁 (국내 인가 업체)

> **업체 확정: 월렛원 (WalletOne).** 2026-04-25 내부 확정. ADR-002 참조.

| 컴포넌트 | 설명 | 소유 |
|---|---|---|
| 커스터디 지갑 | NFT 발행·전송·소각용 Hot/Cold 지갑 | VASP |
| 프라이빗 키(주키) | MPC or HSM 보관. 교보 접근 불가 | VASP |
| 멀티시그 주키 | 2-of-3 or 유사. 교보 보조키와 쌍 | 공동 |
| TX 서명·브로드캐스트 | 교보 요청 → 서명 → 메인넷 전송 | VASP 실행 |

**키 거버넌스 구조:**
```
일반 TX:  VASP 단독 서명 가능
대형 TX:  VASP 주키 + 교보 보조키 = 2-of-2 (or 2-of-3)
긴급 정지: 교보 Admin 대시보드 → 컨트랙트 Pause
```

---

### 5. 퍼블릭 블록체인 — EVM (Ethereum Mainnet 추정)

| 컴포넌트 | 설명 | 소유 |
|---|---|---|
| ERC-1155 NFT 컨트랙트 | 발행·소각·벌크 전송. Pausable·AccessControl | 교보 |
| 거버넌스 컨트랙트 | 정책 변경·권한 관리·멀티시그 실행 | 교보+VASP |
| Chainlink Oracle | KRW/USD 환율 피드 (Phase 2 스테이블코인용) | 외부 |

**컨트랙트 설계 원칙:**
- 오너십: 교보생명 보유
- Pausable: 긴급 상황 시 교보가 전체 정지 가능
- AccessControl: VASP는 mint/burn 권한만, 정책 변경 불가
- Upgradeable: Proxy 패턴으로 업그레이드 가능하게

## 핵심 데이터 흐름

### 흐름 1: NFT 발행 (쿠폰 지급)
```
사용자 앱 (걷기 달성)
    → 이벤트 조건 판단 서버 (내부망)
    → NFT 발행 요청 생성
    → Relayer Service (내부망)
    → VASP API Gateway (내부망)
    → VASP TX 서명
    → EVM 메인넷 브로드캐스트
    → Webhook Receiver (내부망)
    → Redis Streams
    → 내부 원장 업데이트
    → 사용자 앱 알림
```

### 흐름 2: NFT 소각 (쿠폰 사용)
```
사용자 앱 (쿠폰 사용 요청)
    → 딥링크 → 지갑 서명 (사용자)
    → or 교보 앱 내 처리 (커스터디 지갑)
    → 소각 요청 → VASP → 온체인 burn()
    → 원장 업데이트
```

### 흐름 3: 벌크 발행 (이벤트 대량 배포)
```
Admin 대시보드 (교보)
    → 대상자 목록 + 물량 확정
    → 승인 워크플로우 (내부)
    → 멀티시그 보조키 서명 (교보)
    → VASP 멀티시그 주키 서명
    → ERC-1155 safeBatchTransferFrom() or 머클트리 클레임
    → 벌크 배포 완료
```

## 교보가 구축하는 것 vs VASP가 하는 것

| 역할 | 교보 | VASP |
|---|---|---|
| 무엇을 | ✅ 발행 조건, 수량, 대상 결정 | |
| 언제 | ✅ 트리거 타이밍 | |
| 누구에게 | ✅ 사용자-지갑 매핑 | |
| 어떻게 실행 | | ✅ 키 서명, TX 브로드캐스트 |
| 컨트랙트 정책 | ✅ 오너십, Pause, 업그레이드 | |
| 키 보관 | ✅ 보조키 (거버넌스용) | ✅ 주키 (실행용) |
| 원장 관리 | ✅ 내부 원장 직접 운영 | |

## Phase 2 — 향후 (규제 해소 후)

| 항목 | 내용 | 상태 |
|---|---|---|
| 원화 스테이블코인 | **Circle Arc** (EVM 호환 L1, CCTP 내장) 테스트넷 참여 | 2025.12.03 공식 발표 |
| KRW1 스테이블코인 | Arc 위 ERC-20 (BDACS 발행, 우리은행 Escrow 백킹) | Arc 테스트넷 배포 완료 |
| Chainlink Oracle | USDC/KRW 실시간 환율. 보험료·보험금 정산 | Phase 2 연동 예정 |
| XRPL RWA | Ripple Custody 기반 정부채 토큰화 — 2일 결제 → 실시간 | 2025.04.15 공식 발표, 기술검증 진행 중 |
| 직접 커스터디 | VASP 위탁 → 직접 인가 전환 시 커스터디 내재화 | 옵션 열어둠 |

**IBlockchainAdapter가 전환을 단순화하는 방식**
- Phase 1 EVM 어댑터 → Phase 2: XRPL 어댑터·Arc 어댑터만 추가
- 비즈니스 로직·원장·감사 로그 코드는 수정 불필요 (어댑터 주입만 교체)

**Phase 1 → Phase 2 이식 경로 (Arc EVM 호환)**
```
Phase 1 (Ethereum EVM) → Phase 2 (Circle Arc)
  - Solidity 컨트랙트:  그대로 배포 가능
  - Hardhat 스크립트:   RPC URL + ChainID만 변경
  - ethers.js/viem:    그대로 사용
  - 수정 필요:          가스 ETH → USDC, SELFDESTRUCT 제거, KRW1/CCTP 추가
```
Phase 1을 EVM 기반으로 개발하는 것이 Phase 2 Arc 전환의 전제조건.
