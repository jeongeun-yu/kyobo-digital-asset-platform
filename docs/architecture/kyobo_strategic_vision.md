## 1. 핵심 전제 — "오늘 온 담당자의 계획이 아니다"

4/20 미팅에 참석한 교보DTS 담당자들은 실행 레벨이다.  
Circle MOU, Ripple MOU, 원화 스테이블코인, XRPL RWA — 이것들은 **교보생명 오너(임원) 레벨에서 이미 결정된 중장기 전략**이다.

오늘의 교육 프로그램은 그 전략을 **실제로 구현할 팀을 만드는 과정**이다.  
즉, 이 강의는 단순 교육이 아니라 **전략 실행 인프라 구축의 시작점**이다.

### Phase 1 — NFT 라이프사이클 인프라 구축 (현재 진행)

**목표:** 블록체인 기반 디지털 자산 발행·유통·소각 인프라 확보

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 자체 NFT 발행 → 사용자 배포 → 사용 → 소각 |
| 사용 사례 | 걷기 이벤트 달성 시 NFT 쿠폰 지급·소각 |
| 블록체인 | EVM (Ethereum 계열, 확정 미완) |
| 표준 | ERC-1155 (복수 토큰 타입, 배치 전송) |
| 규모 | 벌크 발행 — 수만 명 동시 배포 가능해야 함 |
| 커스터디 | 국내 인가 VASP 위탁 (교보 직접 보유 불가 — 규제) |
| 거버넌스 | 멀티시그/MPC — VASP 주키 + 교보 보조키 공동 통제 |
| 내부 원장 | 교보 직접 운영 (온체인 상태와 실시간 동기화) |
| 레퍼런스 | 신한은행 NFT (클레이튼 기반, VASP 위탁 동일 구조) |

**신한은행 NFT와의 결정적 차이:**
- 신한은행: 마케팅 NFT (토큰뱅크 위탁, 제한된 기능)
- 교보생명: **보험 서비스 핵심 인프라** — 쿠폰·포인트·자산 증명까지 확장 예정

### Phase 2 — 온체인 금융 인프라 확장 (규제 해소 후)

**목표:** 실제 금융 거래(보험료·보험금)를 블록체인으로 처리

| 항목 | 파트너 | 내용 | 상태 |
|---|---|---|---|
| 원화 스테이블코인 | Circle (파트너십 확인) | **Circle Arc** 테스트넷 참여 — 스테이블코인 인프라 기술검증 | **2025년 12월 3일 공식 발표** (국내 유일 보험사) |
| 환율 오라클 | Chainlink | USDC/KRW 실시간 환율 → 보험료·보험금 정산 | Phase 2 연동 예정 |
| RWA 토큰화 | Ripple (파트너십 확인) | XRPL + Ripple Custody 기반 정부채 토큰화 | **2025년 4월 15일 공식 발표** (2일 결제 → 실시간) |

**Circle Arc란?**
- Circle이 개발한 **스테이블코인 금융 특화 Layer-1 블록체인** (ARK가 아닌 Arc)
- 2025년 10월 공개 테스트넷 출시
- USDC를 네이티브 가스 토큰으로 사용 → 변동성 없는 수수료
- CCTP(크로스체인) 통합 내장
- 참여 기관: Goldman Sachs, BlackRock, HSBC, Visa, MasterCard, AWS 등 100개 이상
- **교보생명 = 한국 유일 보험사로 참여**

**Ripple 파트너십 구체 내용 (공식 발표):**
- Ripple Custody 활용한 **정부채(국채) 토큰화**
- 현재 2일 소요되는 국채 결제 주기를 **거의 실시간(near real-time)으로 단축**
- 2025년 4월 15일 공식 발표

**파트너십의 의미:**
Circle·Ripple 파트너십은 **임원 레벨 결정이 공개 발표까지 간** 상태다.  
단순 기술 검토가 아니라 전략적 의지가 외부에 공표된 것 — 후퇴 불가.

**Phase 2가 열리는 조건:**
- 금융당국의 가상자산 관련 규제 완화
- 보험업법상 준비자산 운용 범위 확대
- 교보생명의 VASP 직접 인가 취득 가능성

### Phase 3 — 블록체인 네이티브 보험사 전환 ⚠️ 추론

> 명시 확인 없음. MOU 구조 + 전략 방향에서 추론.

**목표:** 보험의 모든 핵심 프로세스를 온체인으로 이관

| 영역 | 현재 | Phase 3 목표 |
|---|---|---|
| 커스터디 | VASP 위탁 | 직접 인가 취득 → 내재화 |
| 보험료 납입 | 법정화폐 | KRW 스테이블코인 온체인 납입 |
| 보험금 지급 | 수동 심사·이체 | 스마트컨트랙트 자동 조건 실행 |
| 준비자산 운용 | 오프체인 채권·유가증권 | XRPL RWA 토큰화 자산으로 운용 |
| 고객 자산 증명 | 내부 DB | NFT 기반 소유권 증명 (온체인) |
| 규제 감사 | 사후 보고 | 실시간 온체인 감사 |

**이게 현실화되면 교보생명은:**
- 국내 최초 블록체인 네이티브 보험사
- 준비자산이 RWA 토큰으로 운용되는 기관
- 스마트컨트랙트 기반 보험금 자동 지급 체계 보유

## 3. 전략적 구조 해석 — 왜 이 순서인가

```
Phase 1: 인프라 기반 확보 (현재)
  └─ ERC-1155 + VASP 위탁 + 멀티시그 = 온체인 운영 경험 축적
  └─ 내부 원장 직접 운영 = 데이터 자산 확보
  └─ 커스터디 세션 유지 = 직접 인가 취득 옵션 열어둠
  └─ [핵심] EVM 기반 설계 = Phase 2 Arc 이식 시 코드 재작성 없음

Phase 2: 금융 서비스 온체인화 (규제 해소 후)
  └─ Circle Arc (EVM 호환) → Phase 1 Solidity 코드 그대로 이식
  └─ KRW1 스테이블코인 (Arc 위 ERC-20) → 보험료·보험금 결제 레이어
  └─ Ripple Custody → XRPL RWA = 준비자산 토큰화 = 유동성·투명성 확보
  └─ Chainlink → 오라클 = 오프체인 데이터(환율·자산가격) 신뢰성 확보

Phase 3: 완전 통합 ⚠️
  └─ VASP 직접 인가 → 키 주권 내재화
  └─ 스마트컨트랙트 보험 조건 실행 → 보험금 자동 지급
  └─ RWA 운용 → 보험사 자산운용 블록체인화
```

**핵심 인사이트:**  
교보생명은 블록체인을 마케팅 도구로 쓰려는 게 아니다.  
**보험사의 핵심 기능(납입·지급·자산운용)을 블록체인 인프라로 교체하려는 것**이다.  
Phase 1은 그 전환의 첫 번째 실전 검증 단계다.

## 3-1. Circle Arc — Phase 1 → Phase 2 이식 경로 ★

> Arc의 EVM 호환성은 교보 전략에서 가장 중요한 기술적 선택이다.

**Arc 기술 스택 (2026년 4월 기준)**

| 항목 | 내용 |
|---|---|
| VM | **EVM 완전 호환** (Reth 기반 — Rust Ethereum 실행 레이어) |
| 스마트컨트랙트 언어 | **Solidity 100%** — Hardhat·Foundry·ethers.js 그대로 사용 |
| 합의 알고리즘 | Malachite BFT (Tendermint 계열, PoA → PoS 전환 예정) |
| Finality | **100~350ms 결정적 확정** (Ethereum 15분 확률적 대비) |
| TPS | ~10,000 (4 validators) |
| 가스 토큰 | **USDC** (ETH 아님 — 변동성 없는 고정 수수료) |
| KRW1 | BDACS 발행 — Arc 위 ERC-20 (우리은행 Escrow 백킹) |
| 오픈소스 | Malachite: Apache 2.0 공개 / Arc 전체: permissive 예정 |
| 참여 기관 | Goldman Sachs, BlackRock, HSBC, Visa, AWS 등 100개+ |

**Phase 1 → Phase 2 코드 이식 비교**

```
Phase 1 (Ethereum EVM):
  KyoboNFT.sol          → 그대로 Arc에 배포 가능
  AccessControl.sol     → 그대로 Arc에 배포 가능
  GnosisSafe            → 그대로 Arc에 배포 가능
  Hardhat 배포 스크립트 → RPC URL·ChainID만 변경

Phase 2 (Circle Arc):
  가스 납부 코드       → ETH → USDC로 변경 (일부 수정)
  SELFDESTRUCT 사용처  → 제거 (Arc 미지원)
  KRW1 결제 연동       → ERC-20 인터페이스로 신규 추가
  CCTP 크로스체인      → Circle CCTP SDK 연동 추가
```

**즉, Phase 1에서 EVM 기반으로 개발하는 것이 Phase 2 Arc 전환의 전제조건이다.**  
만약 Phase 1을 클레이튼(신한은행 방식)으로 했다면 Phase 2 Arc 이식 시 전면 재작성이 필요했을 것.

**Arc가 Ethereum과 다른 점 (주의 항목)**
- 가스를 USDC로 납부 → 컨트랙트에서 `msg.value` ETH 수수 로직 수정 필요
- Circle 컴플라이언스 블록리스트 강제 적용 → 금융기관 규제 준수에 오히려 유리
- `SELFDESTRUCT` opcode 제한적 지원 → 사용 금지 권장
